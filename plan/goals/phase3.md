/goal Complete Phase 3 ("Cluster and layout runs") of `plan/build_plan.md`. Desired end state: a view can be clustered and laid out over REST as two independent CPU runs — HDBSCAN on a UMAP-reduced clustering space (never on 2D layout coordinates), memberships persisted with probabilities and outlier scores, per-cluster summaries with representatives and source mix, 2D layout points persisted separately — with topics/outliers read APIs, and the whole pipeline proven offline by a planted-structure test that HDBSCAN measurably recovers (ARI-gated), all in a green pytest suite.

Deliverables:

1. Bulk vector loading in `datagraph/core/vectors.py`: given an embedding run's (model, dimensions) and a list of record ids, assemble the float32 matrix + aligned record-id list using batched `IN (...)` queries (chunks of a few hundred) — NOT one query per record (see the Phase 2 review note on `_existing_vector_hashes`; fix that call site to batch the same way while you're there).
2. The `cluster` run type, CPU kind (executes in the ProcessPoolExecutor; the job function must be module-level and picklable; it may open its own SQLite connections via `db_path`). `POST /api/graphs/:gid/views/:vid/cluster` with optional body `{embeddingRunId?, cluster?: {...overrides}}` (cluster overrides merged onto graph config and re-validated). Resolution at POST time: `embeddingRunId` defaults to the latest succeeded embed run for the graph; if none exists, respond 409 with an actionable message naming `POST /api/graphs/:gid/embeddings` — do not create a doomed run. Execution:
   - Population = view-scope records ∩ records having a vector in the chosen embedding run. Records in scope but missing vectors are skipped and counted as `missingEmbeddings` in stats. Empty population → run fails with an actionable error.
   - Clustering space: method `"umap"` → UMAP with configured `nComponents`, `nNeighbors`, `metric` (cosine), `random_state` = config seed; clamp `nNeighbors` to `population - 1` when needed; population < 5 → fail with actionable error. Method `"none"` → normalized embeddings used directly; reject with 422 at POST time if the view population exceeds 20,000 (per the plan).
   - HDBSCAN (the `hdbscan` package) on the clustering space with `metric="euclidean"` and configured `minClusterSize` (default when null: `max(10, round(0.002 * population))`), `minSamples`, `clusterSelectionMethod`, `clusterSelectionEpsilon`, `allowSingleCluster`.
   - Persist one `cluster_memberships` row per record: `cluster_id` (noise = -1), `probability` (`probabilities_`), `outlier_score` (GLOSH `outlier_scores_`; map NaN/inf to 0.0), `is_noise`.
   - Persist one `cluster_summaries` row per non-noise cluster: size, mean probability, `source_mix_json` (counts by source_type), and representatives — centroid computed in the ORIGINAL embedding space (normalized mean of member vectors), members ranked by cosine-to-centroid, filtered to probability ≥ 0.7 (if the filter empties a cluster, rank without it), top 20 record ids stored in order.
   - Progress phases written to `progress_json` as they start: loading → reducing → clustering → persisting. Stats: population, `missingEmbeddings`, clusterCount, noiseCount, durations per phase, effective params echo. `input_refs_json`: `{embeddingRunId, viewId}`.
   - On success: set the view's `default_cluster_run_id` and `default_embedding_run_id`.
   - Cancellation: queued runs cancellable as today; a running CPU job is not interruptible (numba) — document that in the README runs section.
3. The `layout` run type, CPU kind, fully independent of cluster runs: `POST /api/graphs/:gid/views/:vid/layout` with optional `{embeddingRunId?, layout?: {...}}`. Same population rule and 409 behavior as cluster. UMAP `n_components=2` with the layout config (`nNeighbors` clamped the same way, `minDist`, metric cosine, config seed) over the SAME embedding matrix; persist `layout_points` (x, y finite floats) per record; on success set the view's `default_layout_run_id` (and `default_embedding_run_id` if unset). Layout must be creatable before any cluster run exists — this plus the separate tables is the structural proof that clustering never sees 2D coordinates.
4. Read APIs (all resolve the view's default cluster run, overridable via `?clusterRunId=`; 409 with an actionable message when there is none):
   - `GET /api/graphs/:gid/views/:vid/topics` — run refs (clusterRunId, embeddingRunId), noise summary (count, ratio), and per topic: clusterId, size, meanProbability, sourceMix, representativeRecordIds, and a `label: null` placeholder (Phase 4 fills it).
   - `GET /api/graphs/:gid/views/:vid/topics/:topicId` — one topic, same shape.
   - `GET /api/graphs/:gid/views/:vid/topics/:topicId/records` — the topic's representatives as full record payloads, `topK` param (default 12, max 50), ordered as stored.
   - `GET /api/graphs/:gid/views/:vid/outliers` — paged records ranked by outlier_score descending, plus noise members; include each record's clusterId/probability/outlierScore.
5. `scripts/quality_eval.py` per the plan's "Synthetic Dataset and Quality Verification" section, Phase-3 scope: requires `OPENAI_API_KEY`; embeds the synthetic 5k set for real, runs cluster + layout via the pipeline, scores cluster assignments against `metadata.groundTruthTopicId` (adjusted Rand index and NMI over non-noise records), prints a report, exits nonzero if ARI < 0.5. (Running it is a deferred manual acceptance step — it must be ready to run, not run in CI. The trend/spike checks come in later phases.)
6. Offline planted-structure verification (the load-bearing test of this phase): a test-only structured mock provider — constructed with a rendered-text→topic mapping the test builds from the synthetic records — that returns `unit_normalize(topic_centroid + small seeded Gaussian noise)` per text, with well-separated deterministic centroids per ground-truth topic. Feed it through the REAL pipeline via the executor's existing `embedding_provider_factory` injection point: upload ~2,000 synthetic records (slice of the 5k), embed with the structured provider, cluster via the API, then assert ARI ≥ 0.8 between recovered non-noise cluster assignments and ground-truth topics. This proves matrix assembly → UMAP → HDBSCAN → persistence recovers real structure, deterministically, offline.
